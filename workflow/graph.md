# AI OOTD Graph Workflow

## 目的
管理從來源蒐集到 Wiki、HTML 教學簡報及交付的多階段流程。Graph 控制節點順序與錯誤退回位置；每個節點內使用小型 Loop 修正局部問題。

## 節點規劃
| 節點 | 輸入 | 輸出 | 檢查方式 | 失敗時退回 |
|---|---|---|---|---|
| 1. 需求確認 | 訪談結果 | 專案規格 | 與已確認需求逐項比對 | 需求確認 |
| 2. 來源蒐集 | 主題規格 | raw/ 來源清單 | 來源相關性與品質檢查 | 來源蒐集 |
| 3. 書目查證 | 來源清單 | 已查證書目 | 原始頁面、作者、日期、DOI／URL | 書目查證 |
| 4. 證據卡 | 已查證來源 | cards/Sxx.md | 摘要忠實度、限制與可支持主張 | 該來源證據卡 |
| 5. Wiki 整理 | 證據卡 | wiki/*.md | 引用完整度、主題覆蓋、一致性 | 對應證據卡或 Wiki 主題 |
| 6. 覆蓋率關卡 | Wiki | 覆蓋檢查紀錄 | 八大主題是否有足夠證據 | 回到來源蒐集或證據卡 |
| 7. 簡報大綱 | 已通過的 Wiki | slides/outline.md | 初學者順序、案例與來源對應 | Wiki／大綱 |
| 8. HTML 生成 | 確認的大綱與 Wiki | slides/index.html | 只使用已核准內容 | 對應投影片草稿 |
| 9. 獨立審查 | HTML、Wiki、來源 | reports/review.md | 忠實度、引用、完整度 | 出錯的來源卡或投影片 |
| 10. 渲染檢查 | HTML | reports/render-check.md | 瀏覽器呈現、連結、溢出、響應式 | HTML／投影片草稿 |
| 11. 發布交付 | 通過檢查的 HTML | GitHub Pages 與交付紀錄 | 網址可用、版本一致 | 部署設定或 HTML |

## 停止條件
- 重要主張沒有足夠證據時，停止該主張生成並標記待補資料。
- 來源書目或 DOI 無法確認時，不標記為已查證。
- 每個局部修正最多 2 輪；整體審查最多 3 輪。
- 超過輪數仍未通過時，記錄問題與未完成原因，不得虛報通過。

## 原則
只修正出錯節點及其必要下游，不因局部錯誤重做全部內容。內容生成與最終審查應分開執行。
